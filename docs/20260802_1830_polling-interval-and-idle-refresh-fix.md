# 폴링 주기 단축 및 대기 화면 정지 버그 수정

## 요청 사항

1. 모니터링 중 폴링 주기를 30초 → 20초로 단축
2. "포그라운드에 있는데 도착시간이 안 바뀌는 경우가 있다"는 버그 정적 분석
3. (분석 결과에 따른 후속 지시) 모니터링을 시작하지 않아도 포그라운드에 있으면 20초마다 갱신, 백그라운드면 갱신 안 해도 됨
4. "정류장을 통과한 것으로 추정됩니다" 같은 추측성 안내 대신, 놓치면 그냥 조용히 모니터링 종료

## 정적 분석 결과

`renewWakeLock()`이 `pollArrival()`의 try/catch 밖에 있어 예외 발생 시 `ScheduleWithFixedDelay` 반복 작업 전체가 조용히 영구 정지될 수 있다는 가설을 세웠으나(1순위 후보), 실제 재현 확인 과정에서 더 확실한 원인이 드러남:

**확정 원인**: `MainActivity.refreshArrivalPreview()`("모니터링 시작"을 누르기 전 대기 화면의 도착 예정 시간 미리보기)는 최초 1회만 조회하고, 성공 시 다시 스케줄링하는 코드가 전혀 없었음. 실패 시에만 15초 후 재시도(`PREVIEW_RETRY_DELAY_MS`)하는 로직은 있었지만, 성공한 뒤에는 그걸로 끝 — 화면을 계속 띄워놔도 최초 조회 값에서 영원히 고정됨. 100% 재현되는 설계 누락이며, 실제 모니터링(포그라운드 서비스) 중에는 20초 주기 폴링이 정상 동작해 해당되지 않음.

단말(플립, R3CX705W62D) 확인 중 설치된 앱이 v1.1.2.0(오늘 수정 사항 3버전 전)이었던 것도 함께 발견해 최신 빌드로 재설치 후 진행함.

## 수정 내역

### 1. 폴링 주기 단축
- `BusMonitorService`: `scheduleWithFixedDelay` 주기를 30초 → 20초로 변경 (`POLL_INTERVAL_SECONDS` 상수화)
- 부수 효과: `TARGET_MISSING_POLL_LIMIT`(3회) 기준 grace 기간이 90초 → 60초로 단축됨

### 2. 대기 화면 자동 갱신
- `MainActivity.refreshArrivalPreview()`에 20초 주기(`PREVIEW_REFRESH_INTERVAL_MS`) 자동 재조회 추가
- 초기 진입/실패 재시도 시에만 "확인 중…" 로딩 텍스트를 보여주고, 성공 후 자동 재조회는 조용히 숫자만 교체(깜빡임 방지)
- `onStop()`에서 기존에 이미 `retryHandler`를 정리하고 있어, 앱이 백그라운드로 가면 자동으로 갱신 루프가 멈춤
- 모니터링이 시작된 이후에는 이 대기용 루프가 개입하지 않도록 시작 시점에 가드 추가

### 3. 추측성 도착 알림 제거
- 추적 중인 차량을 3회(60초) 연속 못 찾았을 때 "정류장을 통과한 것으로 추정됩니다"라며 도착 알림을 보내던 로직 제거
- 이제 실제로 확인된 도착(ETA 0분)일 때만 도착 알림이 발송되고, 놓친 경우는 조용히 모니터링만 종료
- 해당 분기에서만 쓰이던 `lastEtaMinutes`/`lastLocationNo` 추적 필드와 관련 SharedPreferences 키(`target_last_eta`, `target_last_location_no`)도 죽은 코드가 되어 함께 정리
